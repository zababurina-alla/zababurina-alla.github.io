# Приёмка вида — правило для проверяющей сессии

Эталон — [DESIGN.md](../../DESIGN.md): вид A (пока за флажком `?look=a` — переведённые экраны принимать с ним;
нормы старого вида — DESIGN.md §9, в таблице ниже — в скобках). Владелец за 2 секунды видит: не тот дизайн, пустоты, разные закругления,
разные отступы между блоками, разнобой шрифтов, «сайт 2007 года». Проверяющие при этом писали «всё отлично».
Поэтому приёмка идёт по списку, числом, а не впечатлением.

## Правило (обязательно)

1. Снимки — на **собранном** сайте (`npm run build`, затем `npm run preview -- --port 4180 --strictPort`), учебный
   режим `?demo=1`, ширины **375** (с касанием: `hasTouch`, `isMobile`) и **1280**. Снимок всей страницы бывает с
   «призраками» переходов — каждую находку перепроверь в обычном окне.
2. Найди **минимум 5 расхождений с DESIGN.md** на каждый принимаемый экран (обе ширины вместе). Каждое — строкой:
   `экран · ширина · где (блок, текст) · что видно · пункт DESIGN.md · число (px, сколько разных)`.
3. **«Всё отлично» без списка не принимается.** Нашёл меньше пяти — напиши, какие пункты чек-листа проверил и чем
   (число из замера, снимок), чтобы было видно, что смотрел, а не пропустил.
4. Перед словом «принято» — числа машин, не глаз:
   - `npm test` — сторож шкалы `scripts/design-scale.test.ts` зелёный;
   - `npm run design` — нарушений в файле экрана 0 (или не больше базы, если экран ещё не переведён);
   - `node scripts/design-dom-audit.mjs http://localhost:4180/ --only <экран> --out <папка>` — на экране:
     радиусов ≤ 3 (12, 20, круг), размеров шрифта только из шкалы, начертаний ≤ 3, промежутков между блоками 1
     (24 на 1280, 16 на 375), левых краёв 1.
5. Отчёт владельцу — коротко: «экран, ширины, нашёл N, исправлено M, осталось K (список)».

## Чек-лист (ошибки владельца → как ловить)

| # | Ошибка | Как проверить | Норма |
|---|---|---|---|
| 1 | **Не тот дизайн** | Сравнить с образцом A (DESIGN.md §10): тёплая бумага, листы тоном без обводки и теней, один зелёный, системный шрифт без засечек | Ничего из отвергнутого: финтех-премиум (Mercury/Stripe), буква «Б» в эмблеме, «по-детски» |
| 2 | **Пустоты** | Пустая ячейка сетки; колонка, где справа пусто больше трети; невидимая кнопка держит место; экран, где половина — фон | 0. `layout-audit.mjs` — колонка «пустоты» |
| 3 | **Разные закругления** | `design-dom-audit` → «радиусов» | 8 и 28 (+ круг). Лист в листе — 8 внутри 28 (старый вид: 12 и 20) |
| 4 | **Разные отступы между блоками** | `design-dom-audit` → «промежутков» | Один: 16 (старый вид: 24 на 1280, 16 на 375) |
| 5 | **Края не по одной линии** | `design-dom-audit` → «краёв» | 1: текст заголовка экрана и секции — по краю листов |
| 6 | **Разнобой шрифтов** | `design-dom-audit` → «размеров», «начертаний», «семейств» | Размеры 15/16/20/24/40 (+36–44 заставка), начертания 400/500/600/650, семейство 1 (старый: 15/17/20/26/36/44, 400/500/600, 2) |
| 7 | **Две главные кнопки** | Глазами: две зелёные главные на экране; «+» поверх содержимого (в A — только внутри нижней панели) | Одна главная на экран |
| 8 | **Цвет без смысла** | Красный, оранжевый — только про сроки; цвет вне палитры | `npm test` (цвет вне токенов падает) |
| 9 | **«Сайт 2007»** | Рамка вокруг всего, таблица в сетку, серые градиентные кнопки, подчёркнутые ссылки посреди текста, текст по центру рабочего экрана, эмодзи вместо значков, тень-пятно | 0 |
| 10 | **Срезанный смысл** | Многоточие, срезавшее смысл; вкладки в две строки; кнопка под краем окна | 0. `layout-audit.mjs` — «подписи», «полосы», `--checks` |
| 11 | **Тёмная тема** | То же в тёмной: белые пятна, подложки «дырой» | `npm run visual` — проверка белых пятен |

## Чего сторож не видит (только глаза)

Пустоты внутри листа, композиция, «не тот дизайн», «примитивно». Значения CSS могут быть все из шкалы, а экран —
скучный и пустой. Поэтому пункт 2 правила (5 расхождений) обязателен и при зелёных числах.
