# Живые проверки «сайт → таблица» (контракт v2.1)

Для первого запуска API на копии таблицы, затем — на живой с тестовым клиентом (окно 21:30–23:30, клиента создаёт
и удаляет только сервер). Сайт на имя клиента не завязан: берёт его `id` из `sync.snapshot`. Обратное направление
(правка в таблице → `sync.changes` ≤ 30 с) проверяет координатор.

До API всё прогоняется на учебном сервере: `npm run dev:mock` (`scripts/mock-api.ts`). Что уже прошло там — в
разделе «Прогон на учебном сервере» внизу; раздел 6 — только живьём.

**Как записывать результат** (правило владельца, п. 3): у каждой проверки — счётчики ступеней сайта (панель отладки
`Ctrl+Shift+D`: введено → в очереди → отправлено → принято → отказ → применено → видно в таблице) рядом с
`diag.counters` сервера (`received`, `applied`, `rejectedByCode`, `repeats`). Итог — «верно N из M», не «работает».
Расхождение «принято сервером» ≠ «видно в таблице» — разбираться, не идти дальше.

## Прогон на учебном сервере (15.10.2026)

Всего проверок в списке — 22. На учебном сервере прошли **11**: 0.1 (вход Google — Дмитрий сам), 0.3, 1.1, 1.3, 2.1, 2.2,

вопрос не ответить из Telegram; путь закрыт тестом `liveApi.test.ts`), 6.1–6.3 (только живьём).

Найдено и исправлено по ходу:
- ответ на запись сдвигал курсор журнала — следствия записи («Что изменилось», пересчёты системы) терялись до
  перезагрузки; теперь курсор двигает только опрос, а после каждой записи сайт сразу опрашивает журнал;
- окончательные отказы таблицы (уже отвечен в Telegram, срока уже нет, не тот вариант ответа) показывались только
  звуком — теперь уведомлением с текстом сервера;
- ответа на вопрос с сайта не было — добавлен (`questions.answer`, варианты кнопками, текст и число полем).
